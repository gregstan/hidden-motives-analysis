# `model_recovery_simulation.md`

# Model Recovery Simulation Plan

> **Purpose:** build a recovery-and-geometry layer around the 476-model IC utility-function analysis.  
> The goal is not merely to ask which model wins on human data, but to calibrate whether the model-selection pipeline can recover known utility structures under finite data, stochastic choice, heterogeneous agents, nesting, and behavioral near-equivalence.

This file is written for the coding agent working inside the **Inferring Hidden Motives** codebase. It assumes access to the existing utility-function definitions, IC-analysis machinery, optimizer, nesting-network utilities, parent-child/sibling metadata, payoff-generation tools, and `general_settings` object.

**Implementation principle:** reuse existing functions whenever possible. Do **not** reimplement utility functions, SoftMax choice rules, payoff-grid generation, nesting relations, parent-child anchor logic, IC calculations, warm-start logic, or optimizer routines unless the codebase truly lacks a reusable function.

For broader paper context, read `ihm_starter_pack.md`. This file focuses narrowly on the new **utility-function recovery simulation** and the associated **Average Model Policy Distance** tools.

---

## 1. Purpose: three validation questions

The paper already contains parameter-recovery and model-validation analyses. This new work adds a deeper calibration of the **utility-function search itself**.

The full validation program should distinguish three questions:

### **Question 1 — Parameter recovery**

> Given the correct utility form, can the optimizer recover known parameters?

This is the existing parameter-recovery logic: generate synthetic data from known parameters, fit the model, then compare fitted parameters to ground truth.

### **Question 2 — Utility-function recovery**

> Given data generated by a known utility function, can the IC pipeline recover the generating utility form, a legitimate nested equivalent, or a behaviorally similar model?

This is the new primary analysis. It tests whether the 476-model IC machinery can recover the *structure* of the model, not just its parameters.

### **Question 3 — Data adequacy / information sufficiency**

> As the number of agents and games changes, does recovery quality stabilize before or near the empirical study size?

This asks whether the actual experiment likely collected enough data for stable recovery, under the simulation assumptions. The same idea can be applied both to parameter recovery and to utility-function recovery.

## 2. Core utility-function recovery simulation

The main simulation should proceed as follows.

```text
1. Select one or more generating utility functions.
2. For each generating function, create synthetic bots with known parameters.
3. Generate synthetic binary choices from those bots across binary dictator games.
4. Fit candidate utility functions to the synthetic choices.
5. Rank candidate models using NLL, AIC, and BIC.
6. Evaluate whether the true model, a nested equivalent, or a behaviorally similar model ranks highly.
7. Save detailed per-run outputs and aggregate summaries.
```

The central criterion is **graded recovery**, not binary success/failure.

A literal top-1 win by the true model is nice, but it is too strict as the only standard because:

- finite data create sampling noise;
- SoftMax choice temperature creates stochastic choices;
- random payoff sequences differ in diagnosticity;
- a parent model can collapse into a child when extra parameters are near anchor values;
- two symbolic utility functions can produce nearly identical choice policies over the payoff grid;
- BIC is supposed to prefer simpler models when extra parameters do not buy meaningful fit.

The right question is therefore:

> **Did the IC pipeline recover the behaviorally relevant utility structure?**

## 3. Selecting generating utility functions

The simulation should support multiple ways to choose generating functions. Do **not** assume that the generating utility function is always hand-selected.

Implement a subset-selection utility, roughly like:

```python
select_utility_function_subset(
    all_models,
    mode,
    n_models=None,
    seed=None,
    include_model_ids=None,
    exclude_model_ids=None,
    required_settings=None,
    forbidden_settings=None,
    distance_matrix_path=None,
    ic_results_path=None,
    nesting_info=None,
)
```

The exact signature can vary if the existing codebase suggests a cleaner design.

### 3.1 Hand-selected subset

Use explicit model IDs.

Useful hand-selected models include:

- empirical BIC winner;
- top model for each parameter count `k`;
- direct parents and children of the empirical winner;
- canonical or interpretable models;
- models containing settings strongly favored by the IC analysis;
- models containing settings strongly rejected by the IC analysis.

This mode is best for debugging and targeted demonstrations.

### 3.2 Random subset

Randomly sample model IDs from the full 476-model set.

Requirements:

- use a seed;
- save the selected IDs;
- optionally stratify by `k` or major utility settings.

Pure random sampling is useful, but it can accidentally choose redundant models. Do not rely on pure random sampling alone for the main benchmark suite.

### 3.3 Stratified random subset

Sample while balancing important model properties, such as:

- number of free parameters `k`;
- altruism included/excluded;
- social comparison included/excluded;
- envy/guilt split versus symmetric social comparison;
- exponent settings;
- payoff differences versus single payoffs;
- presence/absence of reference dependence, payoff ratios, min-max forms, and negativity parameters.

This creates a random but scientifically interpretable benchmark set.

### 3.4 Max-min Hamming subset

Use the 14 Boolean utility settings to select symbolically diverse models.

Algorithm:

```text
1. Represent every model as a 14-element Boolean vector.
2. Start with one or more seed models, usually including the empirical BIC winner.
3. Add the model whose minimum Hamming distance to the selected set is largest.
4. Repeat until n_models is reached.
```

This produces a subset whose symbolic utility settings are maximally spread out.

### 3.5 Max-min policy-distance subset

Use **Average Model Policy Distance** to select behaviorally diverse models.

Algorithm:

```text
1. Compute or load a pairwise model-distance matrix.
2. Start with one or more seed models, usually including the empirical BIC winner.
3. Add the model whose minimum policy distance to the selected set is largest.
4. Repeat until n_models is reached.
```

This is often better than Hamming distance because symbolic distance and behavioral distance are not the same thing. Two models can differ on many Boolean settings but behave similarly; two models can differ on one setting and produce very different choice policies.

### 3.6 Optional rejected-settings-excluded subset

Support an optional filter that excludes models containing settings the empirical IC analysis strongly rejected, such as:

- payoff ratios;
- min-max forms;
- midpoint reference dependence;
- exponents applied directly to payoffs.

Use this as a sensitivity analysis, not the main benchmark. Excluding rejected settings can make recovery look easier than it really is.

## 4. Parameter sampling for synthetic bots

The main utility-function recovery simulation should use **heterogeneous bots**:

> All bots in a run share the same generating utility function, but each bot receives its own parameter vector.

Support two parameter-sampling modes.

### 4.1 Uniform parameter sampling

Draw parameters uniformly from their valid bounds.

Use existing bounds from the codebase and `general_settings`. Do not hardcode unless necessary.

Typical bounds in the current project are approximately:

```text
social-preference weights: [-1, 1]
exponents:                 [0.02, 2]
temperatures:              [0.02, 4]
```

Uniform sampling is useful because it is non-circular. It tests broad identifiability across parameter space.

### 4.2 Human-like parameter sampling

Draw parameters from empirical human parameter distributions, using the paper’s results.

This mode answers a different question:

> Given parameters like those estimated in the human data, how well can the pipeline recover the generating utility form?

Label this mode clearly because it uses empirical results. It is useful, but it should not replace uniform sampling.

Run the recovery simulation under these generative SoftMax choice temperatures:

```python
tau_values = [0.5, 1.0, 1.5]
```

Lower `tau` means less stochastic choice and therefore more diagnostic data. Higher `tau` makes recovery harder.

Implementation notes:

- Use `general_settings.choice_temperature` as the default when appropriate.
- Allow each simulation run to override the default.
- Keep the generative choice temperature conceptually separate from any fitted likelihood temperature already used in the model code.

## 6. Synthetic data generation

For each simulation run:

```text
1. Choose generating utility function m_star.
2. Create n_agents synthetic bots.
3. Sample one parameter vector per bot.
4. Generate n_games payoff structures per bot.
5. Compute the bot’s probability of choosing Option A in each game.
6. Sample binary choices from those probabilities.
7. Save the full ground truth.
```

Saved ground truth should include:

- simulation ID;
- random seed;
- generating model ID;
- model settings vector;
- bot ID;
- true parameter vector;
- payoff structure;
- true choice probability;
- sampled binary choice;
- generative choice temperature;
- parameter-sampling mode.

### Payoff structures

The empirical payoff grid is `{1, 2, 3, 4, 5}^4`, so there are:

$$
5^4 = 625
$$

possible binary dictator-game payoff structures.

Hardcode the exhaustive-grid threshold as:

```python
EXHAUSTIVE_PAYOFF_GRID_THRESHOLD = 625
```

Behavior:

- if `n_games >= 625`, use all 625 payoff structures;
- if `n_games < 625`, sample payoff structures uniformly;
- use the same payoff-generation functions already used in the project.

## 7. Fitting candidate models to synthetic data

For the main heterogeneous recovery simulation, fit candidate models at the **bot level** and aggregate across bots.

For each candidate model `m` and bot `i`:

```text
1. Fit model m to bot i’s synthetic choices.
2. Save fitted parameters.
3. Save raw NLL.
4. Save AIC/BIC.
5. Save convergence and optimizer metadata.
```

Aggregate BIC across bots as:

$$
BIC_m = \sum_i \left(2NLL_{i,m} + k_m\log(n_i)\right)
$$

where:

- `NLL_{i,m}` is the negative log-likelihood for bot `i` under model `m`;
- `k_m` is the number of free parameters in model `m`;
- `n_i` is the number of observations for bot `i`.

This is preferable for heterogeneous bot-level fitting because each bot’s parameter vector is estimated from that bot’s data.

Use existing optimizer schedules, warm starts, parent-fair L2 regularization, nesting-aware initialization, and IC functions wherever possible.

## 8. Layered recovery metrics

Recovery should be scored in layers. Save all layers separately. Do not use only one binary success measure.

### 8.1 Exact top-1 recovery

Did the generating model rank first?

```python
exact_top1 = winner_model_id == true_model_id
```

This is the strictest recovery criterion. It is useful, but it is not enough.

### 8.2 Top-k recovery

Did the true model appear in the top `k` models?

Recommended values:

```python
top_k_values = [3, 5, 10]
```

With 476 candidate models, random top-5 recovery is only about 1%. So top-k recovery can be meaningful even when exact top-1 recovery is imperfect.

### 8.3 Rank percentile

Convert the true model’s rank into a bounded score:

$$
\text{rank_percentile} = 1 - \frac{rank(m^*) - 1}{M - 1}
$$

Interpretation:

```text
1.0  = perfect rank
0.5  = middle of the candidate set
0.0  = worst possible rank
```

This gives a correlation-like bounded measure of rank quality.

### 8.4 Delta-BIC of the true model

Compute how far the true model is from the winner:

$$
\Delta BIC_{true} = BIC(m^*) - BIC(m_{winner})
$$

Interpretation:

```text
0       = true model wins
<= 2    = practically indistinguishable
<= 10   = true model remains in the plausible/equivalent set
> 10    = winner is meaningfully favored over the true model
```

Save:

```python
true_within_delta_bic_10 = delta_bic_true <= 10
```

### 8.5 Nested-equivalent recovery

A child model can legitimately beat its parent when the parent’s extra parameters are near the anchor values that make the parent behave like the child.

Use the existing nesting utilities to classify the winner relative to the true model:

```text
exact same model
child of true model
parent of true model
sibling of true model
unrelated model
```

For child winners, inspect the true generating parameters and check whether they are close to the existing parent-child anchor values.

Examples:

```text
altruism absent            -> altruism parameter near 0
exponent absent            -> exponent near 1
fixed self-interest        -> self-interest near 1
symmetric envy/guilt       -> envy and guilt parameters near equal
negativity parameters off  -> positive/negative paired parameters near equal
```

Use the codebase’s existing anchor definitions rather than inventing new ones.

### 8.6 Behavioral-equivalent recovery

The winner may not be the same symbolic model or a clear nested equivalent, but it may still produce nearly identical choice probabilities. That should count as a practical success.

Use normalized policy regret or Average Model Policy Distance.

Example thresholds:

```python
behavioral_equivalence_epsilons = [0.01, 0.025, 0.05]
```

Save Boolean indicators such as:

```python
behaviorally_equivalent_001 = normalized_policy_regret <= 0.01
behaviorally_equivalent_025 = normalized_policy_regret <= 0.025
behaviorally_equivalent_050 = normalized_policy_regret <= 0.05
```

### 8.7 Feature recovery

Each utility form is defined by 14 Boolean settings. Exact model recovery can fail while still recovering the important settings.

Save:

- unweighted feature accuracy;
- weighted feature accuracy;
- false positives by setting;
- false negatives by setting;
- confusion matrix across the 14 settings.

Weighted feature accuracy is defined later in this file.

### 8.8 Rank-distance alignment

For each recovery run, compute the distance from the true model to every candidate model. Then correlate those distances with IC ranking.

Recommended correlations:

```python
spearman(distance_to_true, bic_rank)
spearman(distance_to_true, delta_bic)
spearman(distance_to_true, raw_nll_rank)
```

Interpretation:

- strong positive relation: the IC analysis ranks models roughly by behavioral closeness to truth;
- weak relation: the IC ranking may be driven by complexity penalties, optimization artifacts, or behaviorally distinct model families;
- BIC may diverge from distance more than raw NLL because BIC intentionally penalizes complexity.

## 9. Directional loss metrics

Directional metrics are appropriate when one distribution is treated as the ground truth.

Use directional metrics for:

- human data, where the observed human response is the target;
- synthetic recovery data, where the generating model is the target;
- true-vs-recovered policy comparisons.

### 9.1 Standard NLL for binary responses

When the data are observed binary responses:

$$
NLL = -\sum_t \log q_t(y_t)
$$

where `q_t(y_t)` is the fitted model’s probability of the observed response on trial `t`.

### 9.2 Cross-entropy for continuous policies

When comparing two models that both output continuous probabilities, do **not** sample binary responses just to compute NLL. Use expected NLL, also called cross-entropy.

Let:

```text
p = true/generating model probability of choosing Option A
q = candidate/recovered model probability of choosing Option A
```

Then:

$$
CE(p,q) = -\left[p\log(q) + (1-p)\log(1-q)\right]
$$

This is the expected NLL that model `q` would receive if model `p` generated infinitely many binary choices.

### 9.3 Entropy of the true policy

The entropy of the true policy is:

$$
H(p) = -\left[p\log(p) + (1-p)\log(1-p)\right]
$$

`H(p)` is the irreducible uncertainty in the true stochastic policy. If the true model itself is stochastic, even the correct model has nonzero expected NLL.

### 9.4 Normalized policy regret

Raw NLL and cross-entropy can be hard to interpret. Normalize policy loss against a random-choice model that always predicts `0.5`.

For one binary choice probability:

$$
R_{policy} = \frac{CE(p,q) - H(p)}{CE(p,0.5) - H(p)}
$$

For many agents and games, compute the numerator and denominator as sums or means across all evaluated cases.

Interpretation:

```text
0       = recovered policy is as good as the true policy
0.01    = recovered policy loses 1% of recoverable information
0.05    = recovered policy loses 5% of recoverable information
1       = recovered policy is no better than random guessing
> 1     = recovered policy is worse than random guessing
```

This metric provides an interpretable upper reference point: **random choice**. A recovered model should not be worse than chance.

Implementation notes:

- clip probabilities before logs, e.g., `epsilon = 1e-12`;
- if the denominator is nearly zero because the true model is close to random everywhere, flag the run as low-identifiability;
- for exact expected policy comparisons, normalized policy regret should be nonnegative because the true policy minimizes its own expected cross-entropy.

## 10. Symmetric model-space distance: Average Model Policy Distance

Use the umbrella term:

> **Average Model Policy Distance**

This is a fast behavioral distance metric between utility functions.

It should be usable for:

- comparing any two utility functions;
- building a full 476 × 476 model-distance matrix;
- selecting maximally diverse benchmark subsets;
- interpreting whether top-ranked IC models form one coherent family or multiple distinct clusters;
- defining behavioral-equivalent recovery.

### 10.1 Why use JSD instead of cross-entropy for symmetric distance?

Cross-entropy is elegant, but it is directional. `CE(p,q)` means “how bad is `q` when `p` is the truth?” That is perfect for recovery loss but less ideal for model-space geometry.

For symmetric model comparison, use normalized **Jensen-Shannon divergence** as the primary metric. It is symmetric and bounded.

### 10.2 Entropy and Jensen-Shannon divergence

For two Bernoulli policies with probabilities `p` and `q`, define their midpoint:

$$
m = \frac{p+q}{2}
$$

Binary entropy is:

$$
H(p) = -\left[p\log(p) + (1-p)\log(1-p)\right]
$$

`H(m)` is the entropy of the midpoint policy: the uncertainty of the average of the two policies.

Jensen-Shannon divergence is:

$$
JSD(p,q) = H(m) - \frac{1}{2}H(p) - \frac{1}{2}H(q)
$$

Normalize by `log(2)`:

$$
D_{JS}(p,q) = \frac{JSD(p,q)}{\log(2)}
$$

Interpretation:

```text
0 = identical policies
1 = maximally different deterministic policies
```

For utility functions, average `D_JS` over payoff structures and parameter draws.

### 10.3 Shared reference-parameter averaging

To compare arbitrary utility functions quickly:

```text
1. Draw a full reference parameter vector containing all possible parameters up to max k.
2. Feed the same full vector into both utility functions.
3. Each utility function uses the parameters it needs and ignores irrelevant parameters.
4. Evaluate both utility functions on the same payoff structures.
5. Compute the selected distance metric.
6. Repeat across many parameter draws and average.
```

This produces a distance defined relative to a reference parameter distribution. That is fine. It is a behavioral distance between the choice policies produced by two utility functions under a specified parameter sampler and payoff distribution.

### 10.4 Recommended function

Implement a function roughly like:

```python
compute_average_model_policy_distance(
    utility_function_A,
    utility_function_B,
    general_settings,
    choice_temperature=None,
    n_games=625,
    n_iters=250,
    metric="jsd",
    parameter_sampler="uniform",      # "uniform" or "human_like"
    empirical_param_source=None,
    use_cache=True,
    cache_csv_path=None,
    seed=None,
)
```

Expected behavior:

- if `choice_temperature is None`, use `general_settings.choice_temperature`;
- if `n_games >= 625`, evaluate all 625 payoff structures;
- if `n_games < 625`, sample payoff structures uniformly;
- draw shared full parameter vectors for both models;
- let each utility function ignore unused parameters;
- average the selected metric across games and iterations;
- for symmetric metrics, allow `(A,B)` and `(B,A)` cache reuse;
- for directional metrics, preserve direction.

### 10.5 Metric options

The function should be able to swap metrics.

Recommended options:

```python
metric_options = [
    "jsd",                 # symmetric, bounded, primary geometry metric
    "abs_prob_diff",       # symmetric and intuitive: mean |p - q|
    "cross_entropy_A_to_B", # directional: expected NLL of B when A is truth
    "cross_entropy_B_to_A", # directional: expected NLL of A when B is truth
    "kl_A_to_B",            # directional: CE(A,B) - H(A)
    "kl_B_to_A",            # directional: CE(B,A) - H(B)
    "sym_kl",               # symmetric but unbounded
]
```

Primary recommendations:

- use `jsd` for model-space geometry;
- use `abs_prob_diff` as an intuitive supplement;
- use cross-entropy / KL / normalized policy regret for truth-vs-recovered comparisons.

## 11. Cache-aware pairwise distance computation

Pairwise model distances should be cached. A full 476-model symmetric matrix has:

$$
\frac{476 \times 475}{2} = 113050
$$

unique unordered model pairs.

That is much cheaper than optimization, but the distances will be reused constantly. Precompute and cache them.

### 11.1 Cache requirements

The distance function should:

```text
1. Check whether use_cache=True.
2. Check whether the cache file exists.
3. Search for a row matching the model pair and settings.
4. Return the cached value only if all relevant settings match.
5. Otherwise compute the distance and append/store it.
```

### 11.2 Settings that must match

Cache rows should include at least:

```text
model_A_id
model_B_id
metric
choice_temperature
n_games
n_iters
parameter_sampler
empirical_param_source, if applicable
parameter bounds or settings hash
payoff mode: full_grid vs sampled
seed or seed policy
code version / function version, if available
```

For symmetric metrics like JSD, `(A,B)` and `(B,A)` are interchangeable. For directional metrics, order matters.

### 11.3 Suggested cache files

Possible output paths:

```text
results/model_policy_distance/model_policy_distances_tau_0p5.csv
results/model_policy_distance/model_policy_distances_tau_1p0.csv
results/model_policy_distance/model_policy_distances_tau_1p5.csv
```

or one combined table with settings columns.

## 12. Weighted feature accuracy

Each utility function is described by 14 Boolean settings. Exact model ID recovery can fail while still recovering the important model ingredients.

### 12.1 Unweighted feature accuracy

Let `s_true[j]` be the true model’s value for setting `j`, and `s_hat[j]` be the recovered model’s value.

$$
A_{feature} = 1 - \frac{1}{14}\sum_{j=1}^{14} \mathbf{1}(s_{hat,j} \neq s_{true,j})
$$

Interpretation:

```text
1.0 = all settings recovered
0.0 = no settings recovered
```

### 12.2 Weighted feature accuracy

Some settings matter more behaviorally than others. Weight setting errors by their behavioral importance.

$$
A_{weighted} = 1 - \frac{\sum_j w_j\mathbf{1}(s_{hat,j} \neq s_{true,j})}{\sum_j w_j}
$$

Recommended weight sources:

1. **Behavioral-distance weights**  
   Average Model Policy Distance between model pairs that differ only in setting `j`. This is the preferred default because it avoids circularity with human IC results.

2. **Simulation-derived weights**  
   Average contribution of each setting to recovery difficulty across simulations.

3. **Human-data IC weights**  
   Absolute mean pairwise delta-BIC from the empirical IC analysis. Useful, but label as empirical and potentially circular.

Save all components, not just the final score.

Recommended outputs:

```text
feature_accuracy_unweighted
feature_accuracy_weighted_behavioral
feature_accuracy_weighted_ic_optional
per_setting_false_positive
per_setting_false_negative
per_setting_weight
```

## 13. Nested-equivalence-aware recovery

The codebase already has extensive parent-child and sibling-sibling verification tools. Use them.

Classify recovery outcomes into tiers:

### Tier 1 — Exact recovery

```python
winner_model_id == true_model_id
```

### Tier 2 — IC-equivalent recovery

```python
delta_bic_true <= 10
```

The true model is not necessarily first, but it remains within the plausible BIC set.

### Tier 3 — Nested-equivalent recovery

The winning model is a simpler child of the true model, and the true generating parameters are close to the parent-child anchor values.

This can be a success, not a failure. BIC should prefer a simpler child when the extra parent parameter is effectively inoperative.

### Tier 4 — Behaviorally equivalent recovery

The winning model is behaviorally close to the true model even if it is not nested.

Possible criteria:

```python
normalized_policy_regret <= 0.01
normalized_policy_regret <= 0.025
normalized_policy_regret <= 0.05
average_model_policy_distance <= threshold
```

Thresholds should be configurable and reported transparently.

## 14. Data adequacy and the knee-of-the-curve analysis

The **knee-of-the-curve analysis** asks whether recovery quality stabilizes as more data are added.

The idea:

> Run the recovery simulation across smaller and larger synthetic datasets. Plot recovery quality against the amount of data. If the curve levels off before or near the actual empirical sample size, the study likely collected enough information for stable model recovery under those simulation assumptions.

Vary:

- number of agents;
- number of games per agent.

Suggested grid:

```python
n_agents_values = [10, 25, 50, 73, 100, 150]
n_games_values = [25, 50, 75, 120, 200, 625]
```

Adjust these values based on the actual empirical design and compute budget.

Track:

- exact top-1 recovery;
- top-5 recovery;
- true model within delta-BIC <= 10;
- nested-equivalent recovery;
- behavioral-equivalent recovery;
- normalized policy regret;
- weighted feature accuracy;
- rank-distance correlation.

Define a practical stabilization rule, for example:

```text
normalized policy regret changes by < 0.01 after adding 25% more data
```

or:

```text
weighted feature accuracy changes by < 0.01 across adjacent larger sample sizes
```

This does not prove the empirical dataset is universally sufficient. It shows whether the actual data size lies near the stable region under the simulated assumptions.

### Apply the same idea to parameter recovery

For parameter recovery, vary agents/games and track:

- parameter correlation;
- RMSE;
- sign recovery;
- calibration slope/intercept;
- parameter shrinkage toward zero;
- convergence diagnostics.

This answers how much data are needed to recover parameters, not just model forms.

## 15. Self-consistency / noise ceiling

Finite data and stochastic choice may make exact recovery impossible. Estimate the ceiling directly.

For a fixed generating model and sampling mode:

```text
1. Generate synthetic dataset A.
2. Generate synthetic dataset B from the same model and sampling rules.
3. Run the recovery pipeline on both datasets.
4. Compare winners, top-k sets, features, and policy distances.
```

If two independent datasets generated by the same model often select different winners, then exact top-1 recovery is not a fair standard.

Useful outputs:

- winner agreement between replicate datasets;
- top-k overlap;
- feature-setting agreement;
- distance between replicate winners;
- true-vs-recovered distance compared to replicate-vs-replicate distance.

Interpretation:

> Recovery is good when the recovered model is about as close to the true model as two finite samples from the same true model are to each other.

## 16. Model-space geometry analyses

Average Model Policy Distance can map the geometry of the 476-model utility-function space.

These analyses can help interpret the empirical IC results and the recovery simulation.

### 16.1 Top-model coherence

Compute average pairwise distance among the top `N` empirical IC models.

Suggested values:

```python
N_values = [5, 10, 25, 50]
```

Interpretation:

- low average distance: top models form one coherent behavioral family;
- high average distance: top models contain behaviorally distinct explanations.

This is one of the most useful geometry analyses for the paper.

### 16.2 Top-model heatmap

Create a pairwise distance heatmap for the top 25 or top 50 models.

Annotate models with:

- BIC rank;
- delta BIC;
- `k`;
- key Boolean settings;
- parent/child/sibling status relative to the winner.

This shows whether the winning region is one tight cluster or multiple distinct clusters.

### 16.3 Distance to winner versus delta BIC

For every model:

```text
x-axis: Average Model Policy Distance from empirical BIC winner
y-axis: delta BIC
```

Interpretation:

- strong positive trend: models farther from the winner fit worse;
- far but good models: distinct theories remain competitive;
- close but bad models: subtle behavioral differences matter;
- close and good models: the top-ranked region is a stable behavioral basin.

This is likely one of the most publication-relevant geometry plots.

### 16.4 Sliding-window diversity over rank

For a rank window of size `N`, compute the mean pairwise distance among models ranked `r` through `r + N - 1`.

$$
W_r = \frac{2}{N(N-1)}\sum_{a<b} D(m_a,m_b)
$$

Plot `W_r` over rank.

Interpretation:

- low diversity at the top: top models are coherent;
- increasing diversity: lower-ranked models become more heterogeneous;
- sharp jumps: transitions between model families;
- valleys lower in rank: coherent but poorly fitting alternative families.

### 16.5 Dendrogram / clustering

Cluster models using the distance matrix.

Annotate leaves by:

- BIC rank;
- `k`;
- altruism setting;
- social comparison setting;
- envy/guilt split;
- exponent settings;
- reference dependence;
- payoff ratios;
- min-max forms.

This is likely a supplement or exploratory figure unless it reveals a highly interpretable structure.

### 16.6 2D map of utility-function space

Use MDS or another distance-preserving method to create a 2D map from the distance matrix.

Color by:

- delta BIC;
- `k`;
- model family;
- major settings;
- cluster membership.

This can show whether top-ranked models occupy one island or multiple islands in behavioral policy space.

### 16.7 Feature-level behavioral importance

For each Boolean setting, compute the average policy distance between pairs of models that differ only in that setting.

This complements the existing pairwise delta-BIC analysis.

The IC pairwise analysis asks:

> Does turning this setting on improve empirical fit?

The policy-distance analysis asks:

> Does turning this setting on substantially change behavior?

Interpretation grid:

| Behavioral distance | Empirical BIC improvement | Interpretation |
|---:|---:|---|
| High | High | Feature changes behavior and humans appear to use it. |
| High | Low / worse | Feature changes behavior, but not in the human-supported direction. |
| Low | High | Subtle but systematic improvement; inspect carefully. |
| Low | Low | Feature is probably negligible in this payoff space. |

### 16.8 Discriminating payoff structures

If top models form multiple clusters, identify payoff structures where cluster-average policies diverge most.

For two clusters, compute each cluster’s average choice probability for every payoff structure and find the games where the cluster policies differ most.

These payoff structures are candidates for future experiments designed to distinguish the best remaining utility-function families.

## 20. Guardrails and implementation cautions

### Reuse existing code

Before implementing anything new, search for existing functions that already perform:

- utility evaluation;
- SoftMax choice probabilities;
- payoff-grid generation;
- synthetic choice generation;
- parameter bounds;
- IC calculations;
- optimizer calls;
- parent-child/sibling classification;
- parent-child anchor mapping;
- nesting verification;
- model metadata loading.

The project already has extensive machinery for utility functions, IC analysis, nesting relations, parent-fair regularization, and robustness checks. The new code should wrap and reuse that machinery.

### Keep settings explicit

Every output should store:

- seed;
- choice temperature;
- parameter sampler;
- n agents;
- n games;
- candidate subset;
- generating-model subset;
- metric;
- cache version;
- optimizer settings;
- whether full payoff grid or sampled payoffs were used.

### Do not overinterpret exact recovery

Exact top-1 recovery is only one score. The more mature standard is:

> exact recovery OR IC-equivalent recovery OR nested-equivalent recovery OR behavioral-equivalent recovery.

### Separate geometry from recovery

Use:

```text
JSD / Average Model Policy Distance  -> symmetric model-space geometry
normalized policy regret             -> directional true-vs-recovered loss
BIC / AIC                            -> model-selection ranking
```

Do not collapse these into one number.

# Final framing

This analysis should let the paper say something much stronger than:

> “We compared 476 utility functions and one won.”

The richer claim is:

> **We calibrated the 476-model IC pipeline. When the true utility structure is identifiable, the pipeline should recover it; when exact symbolic recovery fails, we can determine whether the winner is a simpler nested equivalent, a BIC-equivalent alternative, or a behaviorally near-identical policy. We can also test whether the empirical data size is enough for the recovery curve to stabilize and whether the top-ranked empirical models form one coherent behavioral family.**

That is the purpose of this file: build the recovery, distance, and geometry tools needed to turn a giant model comparison into a calibrated scientific instrument.
